# 可选钓鱼群能力

此扩展只对本机明确配置的个人微信群生效。`WCB_FISHING_GROUP_ID` 设置经过核实的真实群 ID，`WCB_FISHING_GROUP_NAME` 设置显示名称；默认未配置时禁用。环境需传入 bridge 与任务 worker，不能只在交互 shell 中设置。宿主同时核对入口账号和真实群 ID，不按昵称、群名或消息正文授予能力；其他群与私聊不加载。

## 调用

`plugins/fishing/SKILL.md` 是群专用使用说明，`src/fishing.ts` 只在目标群生成、审查中加载能力，保留全局 GENERATE.md / REVIEW.md。`fishing_knowledge` 按问题检索 `third_party/bigfish` 中的固定版本资料，默认最多三段；`fishing_weather` 按需调用 Open-Meteo，默认江苏南京浦口、北京时间，可按明确地点或坐标查询。当前、逐小时、逐日天气和气压趋势分别带时间及单位，预报不是水温、溶氧或鱼口实测。

`fishing_assess` 需要另行部署的 FishingCore 评估服务，本仓库只提供调用客户端。通过 `WCB_FISHING_API_URL` 配置服务基址，默认 `http://127.0.0.1:18186`；客户端请求 `POST /v1/assess`，验证服务返回的来源和参考结果结构。服务实现与运维文档由部署者提供，不能假定新机已有该服务。未接入或请求失败时明确返回评估不可用，不生成虚构计算结果。

评估无需浏览器，可按日期、水域、水深、昼夜时段请求，深度对比按需单日计算。当前请求默认地点为浦口，评分主要针对鲫鱼；结果带估计范围、默认假设和时间，不能当成上鱼概率或实测。

工具由现有 app-server 动态工具接口执行，兼容当前 API 转发链路。不是另起一个钓鱼人格或服务；不运行上游安装脚本，不把知识文件全量塞进提示词。上游来源、许可和数据适配见 `third_party/bigfish/SOURCE.md`。

## 记忆边界

- 知识文件独立存放；天气客户端使用短期内存缓存，评估服务自行负责其缓存。所有工具结果沿相同隔离规则，不写入人物长期记忆或向量库。
- 本群阮阮的全部出站答复在实际投递后，原子写入 `memoryPolicy: {excludeFromLongTerm:true, source:'fishing_tools'}`。包括未再次调用工具的后续转述，避免旧资料从另一轮答复重新进入记忆。
- 原始聊天、发送回执和群上下文保留，可接续当前话题。长期整理、提交和向量索引均跳过这些答复；已有索引的来源标记变化会触发分块刷新。
- 本群生成与审查都不提交生活 `state`，不会因为谈钓鱼而让生活心跳误以为她正在钓鱼。使用工具的回合也不提交工具衍生 `stance`；普通相处中的持续边界仍可保存。
- 群友自己明确说出的偏好、真实经历仍可按来源保存，正常 `social`、好感和关系变化继续起作用。其他会话的普通人物记忆规则不变。
- 启用扩展不清除既有聊天；外部资料按上述来源规则隔离。

## 验证

离线测试使用临时目录和模拟网络/模型，覆盖群隔离、工具返回、审查依据、发送时标记、后续转述、长期整理、向量索引和真实用户事实保留，不创建正式聊天。部署后分别核对目标群配置、外部服务可用性和真实工具注册；离线通过不代表外部服务已就绪。新工具在下一次 `thread/start` 注册，更新时保留原始群聊天和记忆，不通过清空数据启用能力。
